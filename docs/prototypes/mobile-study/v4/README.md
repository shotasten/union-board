# v4：予定カセットに統合

[試作を開く](http://localhost:8765/v4/)

- タブを撤去し、日程・場所・参加予定人数（○＋△）・○△内訳・自分の回答を常に表示。
- 日程・場所・人数は詳細画面へ。「自分」は独立したボタンで、未選択ならメンバー選択後に押した日程の編集へ、選択済みなら直接その日の編集モーダルを開く。
- 表示領域310px未満では自分の回答を下段へ配置。幅が足りる場合は横並び。
- 未選択なら自分：未選択。選択・任意の端末記憶・詳細からの出欠変更・未定の一括入力は維持。
- v3とは保存キーを分離。本体・本番は変更せず、保存は端末内のみ。個人別内訳はサンプル。

起動は前版と同じサーバーで、URL末尾を /v4/ にします。

## 検証

絶対配置を削除し、日程本体と自分の回答をGridの別領域に配置。320・360・390・400・480・800・860pxの7幅で横はみ出しと人数／回答ボタンの矩形の重なりがないこと、回答ボタンの高さ44px以上を確認。狭い画面は下段、幅が足りる画面は横並びです。日程部分は詳細へ遷移。「自分」は未選択→山田選択→2/6のみの編集、選択済み→2/14のみの編集を操作確認。山田の2/6を○へ保存し、参加予定9→10と自分の記号の更新を確認しました。実機操作は未確認です。

Modern Web Guidanceのform-factor-adaptationを参照し、コンテナ幅に応じて配置を変えています。

## カセット全体と内側のボタン

360〜400pxでは日程・場所・人数・回答ボタンを横並びにします。320pxでは下段へ配置します。カセット全面に詳細リンクのタップ領域を広げ、ボタン周囲の余白も詳細を開けます。出欠ボタン自体は独立した編集操作で、リンク内にボタンを入れ子にはしません。ホバー・キーボードフォーカスもカセット全面に表示します。

320・360・390pxで人数と回答ボタンの重なりなし、320・360・390・400・800pxで横はみ出しなしを確認。390pxではボタン周囲の余白が詳細リンク、ボタン中央が編集ボタンとなるヒット領域を確認し、編集と詳細への遷移を操作確認しました。旧検証時の幅基準をこの配置に更新しています。Modern Web Guidance の card の stretched-link パターンを適用。

## 内訳の表示切替

日程詳細に「パート別」「全体一覧」のタブを追加しました。全体一覧は現行と同じイベントが行・メンバーが列の12×40表です。8パートのグループ見出しと40人の名前を2段ヘッダーにし、表内を横スクロールできます。ヘッダーと左の日程は固定し、開いている日程には「選択中」と枠線を表示。名前から個人の12日程を確認できます。セルは表示専用で、回答は既存の編集モーダルから変更します。

390pxで12行・480セル・8パート、タブの表示パネルが1つ、ページ全体の横はみ出しなしを確認。横スクロール720px後も左の日程ヘッダーが固定されること、左右キーでタブが切り替わることを操作確認しました。選択状態は下線でも示します。Modern Web Guidanceのtabsとresponsive-tableを参照（CLIの一時ファイル消失のためインストール済みガイドを直接参照）。
