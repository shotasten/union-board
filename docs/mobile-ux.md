# スマホ向け出欠UX

## 画面と機能

トップは予定一覧です。日程・時刻・場所・参加予定人数（○＋△）・○△の内訳・自分の回答を同じ行で確認します。カセット全体から日程詳細へ進み、内側の自分の回答ボタンは別の操作として当日の出欠編集を開きます。狭い画面では自分の回答を下段へ配置します。

入口は「自分の名前を選ぶ」に統合し、「あなたの名前は？」でパートを選んでから、そのパートの既存の名前を選びます。初めて利用する人向けの「メンバー登録」は選択欄より前に置き、未選択でも登録入口が見つかるようにします。主操作はフォーム幅いっぱいに配置し、閲覧だけの場合は右上の「登録せずに見る」で閉じます。名前がない場合は同じ画面で名前を入力し、「登録して進む」で本人として選択されます。未選択で回答を押した場合は、選択後に元の日程の編集を開きます。任意でスペース別のlocalStorageにuserKeyのみを保存します。取得成功後に最新のメンバー情報と照合し、削除済みなら選択を解除します。取得失敗時は保持します。以前保存された表示名とパートは削除します。これはログイン・本人認証ではなく、他人の編集防止にもなりません。名前やパートが変わってもIDで選択を維持します。共有端末では「この端末で覚える」を外し、必要なら本人選択を解除します。

本人選択後は、未定の一括入力・全日程の変更・名前とパートの編集が使えます。日別編集と一括編集は変更した日程だけを既存の保存APIへ送ります。未回答を開いただけでは未定として保存しません。保存失敗時は入力を保持し、トーストでエラーを通知します。外側タップや取消は保存せず編集を閉じます。

日程詳細は次の順序です。

1. 日程・時刻・場所・人数・説明
2. コメント本文（投稿者・出欠記号を併記、追加操作なしで表示）
3. 管理者の場合のみイベント編集・削除
4. 固定タブ「パート別」「全員の出欠」

全員の出欠はその日だけの名前と回答をパートごとに縦に表示します。パート集計から当該パートへ絞れます。名前から従来のメンバー編集を開き、各日程・名前・パートの変更ができます。未回答と未定はともに「-」。0件の内訳も「-」です。退会した人の回答は人数・コメントから除外します。

日程を横断する表は予定一覧の「日程 × メンバーの全体表」から引き続き使えます。日程詳細は #event/<eventId>、予定一覧は #schedule で、ブラウザーの戻る・進むに対応します。表示期間外・削除済みの詳細URLは予定一覧への案内を表示します。

## 一般メンバーと管理者

|一般メンバー共通|管理者に追加|
|---|---|
|メンバー登録、本人の名前・パート編集|イベント登録・編集・削除|
|出欠・コメントの閲覧と入力|表示期間の設定|
|自分のGoogleカレンダーに追加|新年度リセット|
|最新表示|管理者管理・招待・同期・ログアウト|

メンバー向けのカレンダー追加と管理者の同期を混同しません。これらの既存API・認証・登録処理は継続使用します。UI上で隠すことを権限確認の代替にはしません。

## デザイン

ブランドは既存icon-192.pngのターコイズ #2DB0BC、主要操作と文字には読みやすい濃色 #087B86。白い情報面・濃紺の主文字・共通の余白と角丸を使い、出欠色は記号と併用します。モーダルはnative dialogで外側タップ・Escape・閉じるボタンに対応し、保存中は閉じる操作を止めます。未対応ブラウザーでは外側の領域を判定します。既存の管理者・メンバー情報モーダルは既存処理を保ちながらスマホ向けに整えています。

## 確認方法

通常の開発はREADMEの環境変数設定後、npm ci / npm run dev を使います。

本番に接続せず画面を確認する場合は、開発サーバーで /tests/fixtures/attendance-preview.html を開きます。これは本体コンポーネントを12日程×40人・8パートのサンプルで描画し、Supabaseを読み込みません。共通のカレンダー追加・最新表示の操作バーと、名前選択に統合した登録フォームを表示し、登録と出欠保存はブラウザーのメモリーで再現します。プロフィール・管理者の実操作は行いません。「保存失敗を再現」でエラー時の入力保持も確認できます。本番ビルドの入口には含まれません。

検証済み：

- npm run lint（既存の警告2件、エラー0件）、npm run typecheck、npm test（32件）、npm run build。
- npm audit --audit-level=high は成功。既存のmoderate 11件は今回の依存変更ではなく、依存関係の更新は実施していません。
- 320・360・400・1024pxで一覧の横はみ出し・人数と回答ボタンの重なりなし。
- 未選択から山田（Tp）を選択→元の1日程の編集→保存、未定2件の連続入力と保存。
- 保存失敗時に出欠とコメントを保持、取消とモーダル外タップで閉じる。
- 本人の記憶、全体表の横スクロール、コメント常時表示、40人表示、固定タブ、Tp5人への絞り込みとフォーカス、管理者表示。

実機・Safariでの確認、および本番への保存・同期は未実施です。ビルド時のカレンダー埋め込み用環境変数未設定とチャンクサイズの警告は残っています。

## スコープ

試作から本体へ移すことに合意した後の実装です。作業はcodex/mobile-experience-studyの既存worktreeで行い、元のチェックアウトの未コミット変更には触れていません。マージ・デプロイは行いません。

表示期間による取得範囲の最適化は [Issue #75](https://github.com/shotasten/union-board/issues/75) で別PRに切り出し、今回src/lib/api.ts・DB・同期処理は変更しません。

独立した「メンバー登録」は撤去し、名前を選ぶ入口に統合しました。出欠ボタンから名前選択へ進んだ場合は、既存の人を選んでも新規登録しても、元の日程の編集へ戻ります。同じパート・名前があれば重複登録せず既存の名前の選択へ戻します。登録失敗時は入力した名前とパートを保持します。既存の登録処理の成功時に新しいMemberを受け取り、そのuserKeyを本人として設定します。

統合後の追加確認：既存の山田（Tp）選択、新規サンプル登録から2/14のみの出欠編集へ進むこと、登録失敗時の名前保持、山田の重複入力時にTp1の選択へ戻ることを、本番非接続の確認画面で操作確認しました。

## PC幅と初回案内

本体と確認画面の両方で、メインコンテンツの最大幅を75rem（標準文字サイズで1200px）とし、左右の余白を12〜32pxにして中央寄せします。ヘッダーは背景と内部コンテンツの両方を全幅にし、左右の余白だけ12〜32px取ります。フッターは背景を全幅にし、内部要素をメインと同じ最大幅・左右余白で揃えます。全体表はメイン幅の内側だけ横スクロールします。

本人が未選択で、同じタブ内に閲覧へ進んだ記録がない場合は「あなたの名前は？」を最初に開きます。名前を選ぶ利点と閲覧には登録不要であることを案内し、右上の「登録せずに見る」で閲覧へ戻れます。案内を閉じた状態はスペース別のsessionStorageで同じタブの閲覧中だけ保持します。端末を覚えるチェックは初期ONで、共有端末では外すよう明記しています。未選択のまま閲覧する場合も、名前選択ボタンの下に短い案内を残します。

1440pxと1920pxで最大幅1200px、320pxと390pxで横はみ出しなしを確認。初回の自動表示とチェックON、登録せずに見る→再読み込みで案内なし、名前を覚えて選択→再読み込みで選択を保持し案内なし、を操作確認しました。

幅調整後、1440pxのブラウザーでヘッダー背景1425px・ヘッダー内は左右約29px余白・メイン1200px・横はみ出しなしを確認しました。

本人選択後は名前ボタンから本人を切り替えたり、名前とパートの編集を開いたりできます。名前の選択と出欠変更をコーラル色の主操作とし、名前・パートの編集はテキスト操作で表示します。

予定一覧の見出し右側にカレンダー追加と最新表示を配置します。狭い画面では折り返します。

データ取得中は全画面にローダーのみを表示し、取得完了後に画面を表示します。
